概要

CastSieve は、生成AI画像に埋め込まれたプロンプトからキャラクターを自動で判別し、キャラクター名のフォルダに仕分ける Windows アプリです。判別には Danbooru のタグ情報(カテゴリ "character")を使うので、キャラクター名のリストを自分で用意する必要はありません。

  • 対応する画像: PNG / JPEG / WebP
  • 対応する生成ツール: AUTOMATIC1111 / Forge、NovelAI、ComfyUI、InvokeAI
  • 元の画像は、標準ではコピーして仕分けます(移動も選べます)
  • 先に「解析して確認」で、ファイルを触らずに仕分け先を確認できます。「この結果で実行」は、その確認した内容のとおりにコピーまたは移動します(解析のやり直しはしません)

画面の見かた

画面は上から順に、フォルダ指定(入力・出力)、オプション(タブ)、ボタン、結果の集計、結果の一覧、進行状況になっています。

場所役割
入力フォルダ仕分けたい画像が入っているフォルダ。「参照...」で選ぶか、フォルダをここ(または結果の一覧、ウィンドウの余白)へドラッグ&ドロップします。ファイルを落とすと、そのファイルのあるフォルダになります
出力フォルダ仕分け結果を作る場所。入力フォルダを選ぶと(空欄のとき)、その中の sorted が自動で入ります。ここにもドラッグ&ドロップできます
オプション内容ごとにタブで分かれています。「基本」(サブフォルダ、操作、複数キャラ)、「判別 (Danbooru)」、「画像から推定」、「仕分け先」(フォルダ名、不明・メタデータなしの扱い)、「上書きリスト」(キャラクターごとのフォルダ名を指定するファイル。後述。ファイルをドラッグ&ドロップしても指定できます)。タブの中は横に並び、入らないぶんは次の行へ折り返します。タブの高さは、一番高いタブに合わせています
解析して確認画像を読み取ってキャラクターを判別し、仕分け先を一覧に表示する。ファイルは変更しない。青い塗りつぶしのボタンです
この結果で実行解析した結果のとおりにコピーまたは移動する。解析の結果があり、実行の対象が1件以上あるときだけ押せる(押せないときは薄い色になります)
中止処理を途中で止める(処理中だけ押せます)
結果の集計解析が終わると、一覧の上に件数が出ます(解析した件数、実行の対象、対象外、キャラクターの種類、複数キャラ、不明、メタデータなし)。実行したあとは、完了と失敗の件数も足されます。設定を変えて結果が無効になると消えます
結果の一覧ファイル名、メタデータの種類、検出したキャラクター、仕分け先、状態。行は1行おきに薄い色が付きます。「状態」は色で見分けられます(実行待ち=青 / 対象外=灰 / コピー済・移動済=緑 / 失敗=赤)。列の見出しをクリックするとその列で並べ替わり(▲=昇順)、もう一度クリックすると逆順(▼=降順)になります。標準はファイル名の順です。行をダブルクリック(または Enter)すると、その画像を開きます
下部の進行バー現在の段階(読み取り / Danbooru 照会 / 仕分け先の決定 / コピー・移動)と進み具合

フォルダ別のグループ表示。結果の一覧は、仕分け先のフォルダごとにまとまって表示されます。見出しにはそのフォルダの件数が出て、見出しをクリックすると折りたためます。_ で始まる特別なフォルダ(_unknown など)は、最後に並びます。メニューの「表示」→「フォルダ別にグループ表示」でオン/オフできます(次回の起動でも引き継がれます)。複数のフォルダに入る画像は、最初のフォルダのグループに出ます。

並べ替えと、画像を開く。列の見出しをクリックすると、その列の文字で並べ替えます。ファイル名の数字は数の大きさで比べます(img2 は img10 より前)。同じ値どうしはファイル名の順です。グループ表示がオンのときは、グループの中で並べ替わります。行をダブルクリックするか、右クリックの「ファイルを開く」を選ぶと、画像が Windows の標準のアプリで開きます。移動した後は、移動先のファイルを開きます。

サムネイル。結果の一覧には、画像の縮小表示(サムネイル)が出ます。メニューの「表示」→「サムネイルを表示」でオン/オフ、「サムネイルの大きさ」で小・中・大を切り替えられます。この設定は次回の起動でも引き継がれます。

  • サムネイルはメモリの上だけで作り、ディスクには保存しません。アプリを閉じると消えます
  • 画面に見えている行の分だけを作ります。枚数が多くても、最初にまとめて作ることはありません
  • 動作が重いと感じたときや、サムネイルが不要なときは、オフにしてください。オフにすると、サムネイルの処理はまったく行われません
  • スクロールで見えなくなった行のサムネイルは、一定数(約300枚)を超えると捨てます。もう一度見えたときは作り直します

ダークモード。メニューの「表示」→「テーマ」で、「システムに合わせる」(標準)/「ライト」/「ダーク」を選べます。「システムに合わせる」のときは、Windows の設定(個人用設定 → 色 → 既定のアプリ モード)に従い、Windows 側で切り替えるとアプリもすぐに切り替わります。この設定は次回の起動でも引き継がれます。この説明書もテーマに合わせた色で表示されます。

  • 確認のメッセージやフォルダを選ぶ画面など、Windows 標準の画面はダークにならないことがあります
  • 数値の入力欄(最小投稿数・しきい値)の上下ボタンは、ダークでも明るい色のままです

基本の使い方

まず「解析して確認」で仕分け先を確かめ、問題なければ「この結果で実行」を押します。最初は数十枚の小さなフォルダで試すのがおすすめです。

  1. 「入力フォルダ」の「参照...」で画像のフォルダを選ぶ(フォルダをウィンドウへドラッグ&ドロップしても指定できます)
  2. 「出力フォルダ」を確認する(空欄なら選ぶ)
  3. 必要ならオプションを調整する(標準のままでも使えます)
  4. 「解析して確認」を押す。一覧に「検出キャラクター」と「仕分け先」が出る(ファイルは変更されません)
  5. 結果を確認する。想定と違う画像があれば、一覧で右クリックして仕分け先を手で直すか(下記)、オプションや上書きリストで調整して、もう一度「解析して確認」を押す
  6. 「この結果で実行」を押す。「移動」を選んでいる場合は確認ダイアログが出るので、「はい」を選ぶ
  7. 下部に「N 件をコピー(移動)しました」と出たら完了。一覧の「状態」列と、出力フォルダを確認する
  • 「この結果で実行」は、解析の結果をそのまま使います。メタデータの読み取りや Danbooru への問い合わせを、もう一度行うことはありません
  • 解析の前や、解析の結果がない間は、「この結果で実行」は押せません。実行の対象が0件のときも押せません
  • 入力・出力フォルダや、判別・推定・仕分けのオプションを変えると、解析の結果は無効になります(一覧が灰色になります)。もう一度「解析して確認」を押してください。ただし、「操作」(コピー/移動)だけは、解析の後に変えても結果は有効です
  • 実行した解析の結果は、もう一度実行できません(移動した画像や、コピーの重複を避けるためです)。続けて仕分けるときは、もう一度解析してください
  • 解析のあとに元のファイルが消えたり動いたりしていたら、その画像だけ「失敗」になり、ほかの画像は続けて処理します
初回だけ時間がかかります。初めて見るタグを Danbooru に問い合わせるためです。結果はパソコンに保存されるので、2回目以降は通信せず速くなります。

仕分け先を手で指定する

解析のあと、実行の前なら、画像ごとに仕分け先を手で決められます。_unknown に入った画像や、推定が外れた画像を直すのに使います。

  1. 結果の一覧で、直したい画像を選ぶ(Ctrl や Shift を押しながらクリックすると、まとめて選べます)
  2. 右クリックする。推定の候補があれば「候補: キャラクター名」が並ぶので、選ぶとそのフォルダに決まる
  3. 候補にないときは「仕分け先を指定...」(または F2 キー)を選び、フォルダ名を一覧から選ぶか入力して「OK」を押す
  4. 「この結果で実行」を押す
  • 手で決めた画像は、「仕分け先」の列に「(手動)」と付きます
  • 「候補」は、画像からの推定で、しきい値には届かなかったキャラクターです(確信度の高い順)。キャラクターが決まらなかった画像では、「検出キャラクター」の列に「候補: 名前 確信度」の形で出ます
  • 手で決めた画像は、「キャラクター不明の画像も仕分ける」などをオフにしていても、実行の対象になります
  • 右クリックの「自動の仕分け先に戻す」で、解析で決まった仕分け先に戻せます
  • 手で決めた内容は、今回の解析の結果にだけ反映されます。設定を変えたり、もう一度解析したりすると消えます。毎回同じキャラクターを直しているなら、上書きリストに書いておくと手間が減ります

キャラクター判別の仕組み

CastSieve は、プロンプトのタグを1つずつ、次の順で調べます。上から順に試し、決まった時点で終わります。

1. 上書きリスト自分で書いたタグがあれば、指定したフォルダ名で決定します
▼ 書かれていなければ
2. 保存済みの結果過去に調べたタグなら、通信せずに判定します(見つかったタグは30日間保存)
▼ 保存されていなければ
3. Danbooru に問い合わせカテゴリが character ならキャラクター。タグが見つからなければ、別名を探して再判定します
▼ 接続できなかったタグは
4. 簡易判定Danbooru に接続できなかったタグだけ、「名前 (作品名)」の形のタグをキャラクターとみなします

キャラクターとみなす条件は、Danbooru でカテゴリが character のタグであることです。(cosplay) が付くタグは対象外です。

別名の読み替え。ganyu のように Danbooru に直接は登録されていない略称でも、別名として登録されていれば、正式なタグ(ganyu_(genshin_impact))に読み替えて判定します。

通信する内容。Danbooru に送るのはタグの名前だけです。画像、ファイル名、フォルダ名は送りません。リクエストは1秒あたり4件までに抑えています。

結果の保存。調べた結果は %LOCALAPPDATA%\CastSieve\danbooru_tags.json に保存されます。見つかったタグは30日間、見つからなかったタグは3日間使い回します。

画像からキャラクターを推定する

「メタデータなしの画像は画像から推定」をオンにすると、メタデータが消えた画像でも、画像に描かれた内容からキャラクターを推定して仕分けます。メタデータがある画像は、まずプロンプトから判別します。タグからキャラクターが見つからなかったときだけ、画像から推定します(「タグでキャラクターが分からない画像も推定」がオンのとき。オフなら推定せず _unknown に入ります)。

  1. オプションの「メタデータなしの画像は画像から推定」にチェックを入れる
  2. 初回だけ、推定モデルのダウンロードを確認するダイアログが出る。「はい」を選ぶと、数百MB以上のファイルを Hugging Face から取得して保存する(2回目以降は不要)
  3. 「解析して確認」で結果を確認する。推定で決まった画像は、一覧の「メタデータ」の列が image-ai と表示される(メタデータのある画像は a1111 + image-ai のように形式名が付く)
  • 推定の結果は、確実なものではありません。まず「解析して確認」で確認してから実行してください
  • Danbooru に投稿の多い、有名なキャラクターほど当たりやすく、マイナーなキャラクターや自作キャラクターは苦手です
  • キャラクターが見つからなかった画像は _unknown に入ります。しきい値に届かなかったキャラクターは「候補」として一覧に出るので、右クリックで仕分け先にできます(仕分け先を手で指定する)。推定の途中で失敗した画像は _no_metadata に残り、ログのエラー列に理由が出ます
  • 推定は、画像1枚ごとに計算します。「GPUを使う」がオンなら、まず GPU(DirectML)を試します。解析が終わったときの下部の表示に、実際に使った計算装置(GPU または CPU)が出ます
  • GPU が使えない、または途中で失敗したときは、自動で CPU に切り替わり、その旨が表示されます。GPU は推定の計算だけに使います(画像の読み込みや縮小は CPU です)。速くなる割合は、パソコンやモデルによって変わります
  • 推定した結果は上書きリストにも従います。たとえば hatsune miku,初音ミク と書いておけば、推定でも「初音ミク」フォルダに入ります
  • ダウンロードできないときは、モデルのファイル(model.onnx と selected_tags.csv)を %LOCALAPPDATA%\CastSieve\models\モデル名\ に自分で置いても使えます

仕分け先フォルダとログ

出力フォルダの中に、キャラクター名のフォルダと、次の特別フォルダができます。

フォルダ入る画像
キャラクター名(例: frieren)そのキャラクターが検出された画像
_multiple複数のキャラクターが検出された画像(「複数キャラ」の設定が標準のとき)
_unknownメタデータはあるが、キャラクターのタグが見つからなかった画像
_no_metadataメタデータがない、または読み取れなかった画像

フォルダ名に使えない文字(: / ? " < > | など)は _ に置き換わります。たとえば kafka (honkai: star rail) は kafka (honkai_ star rail) になります。同じ名前のファイルがあるときは、_1、_2 を付けて上書きを防ぎます。

ログファイル。「この結果で実行」を押すと、出力フォルダに sort_log_日時.csv ができます。Excel で開けます。列は、元のファイル、メタデータの種類、検出したキャラクター、仕分け先、エラーです。移動してしまった画像の行き先を探すときに使えます。

上書きリストの書き方

上書きリストは、判別の結果を手で直したいときに使います(任意。なくても動きます)。特定のキャラクターのフォルダ名を好きな名前にできます。ここに書いたタグは、Danbooru の判定より優先されます。

テキストファイル(UTF-8)を作り、1行に1つ、「タグ,フォルダ名」の形で書きます。# で始まる行はコメントです。

# 例
hatsune miku,初音ミク
frieren,フリーレン
rem (re:zero),レム
  • タグは、プロンプトに書かれている英語のタグをそのまま書きます(大文字小文字、_ と空白の違いは区別されません)
  • フォルダ名を省略してタグだけ書くと、そのタグ名のフォルダになります
  • 同じキャラクターの別名タグを同じフォルダ名にすれば、フォルダを1つにまとめられます

作ったファイルは、オプションの「上書きリスト」タブの「参照...」で選びます。ファイルを「ファイル」欄にドラッグ&ドロップしても指定できます。

ほとんどの画像が _no_metadata に入る画像からメタデータが消えています。SNS への投稿や、画像編集ソフトでの書き出しで消えることがあります。生成ツールが出力した元のファイルで試してください

「Danbooruに接続できなかった」と表示されるネットワークかファイアウォールの問題です。接続できなかったタグだけ、名前 (作品名) 形式の簡易判定になります。接続を直してもう一度実行すれば、足りない分だけ問い合わせ直します
関係ないタグがキャラクター扱いされる「最小投稿数」を 50〜100 に上げてください。それでも残るものは、上書きリストでそのタグに別のフォルダ名を割り当てます
同じキャラクターが別々のフォルダに分かれる略称と正式名など、別のタグで書かれています。上書きリストで同じフォルダ名を指定するとまとまります
「この結果で実行」が押せない解析の結果がない、設定を変えて結果が無効になった、実行の対象が0件(すべて「対象外」)、または実行済みのどれかです。もう一度「解析して確認」を押してください。対象が0件のときは、「キャラクター不明の画像も仕分ける」「メタデータなしの画像も仕分ける」を確認してください
GPUを使っているのか分からない / 遅い解析が終わったときの下部の表示に、推定に使った装置が出ます。「CPUに切り替えました」と出ている場合は、GPU のドライバを更新するか、「GPUを使う」をオフにしてください
初回の処理が長い初めて見るタグを Danbooru に問い合わせているためです。1秒あたり4件までに抑えているので、タグが多いと数分かかることがあります。結果は保存されるので、次回からは速くなります

保存済みの結果を消したいとき: Danbooru の照会結果は %LOCALAPPDATA%\CastSieve\danbooru_tags.json に保存されています。このファイルを削除すると、次回の実行ですべて問い合わせ直します。

制限事項

  • NovelAI の「ステルス PNGInfo」(画像のアルファチャンネルに埋め込まれた形式)は読み取れません
  • メタデータが消えた画像は、標準では判別できません。「画像から推定」をオンにすると、有名なキャラクターに限って推定できます
  • 判別できるのは、プロンプトに書かれたキャラクターだけです。画像に実際に写っているかどうかは見ていません
  • Danbooru に登録されていないキャラクターは、上書きリストで指定しない限り判別できません(名前 (作品名) 形式のタグだけは、接続できなかったときの簡易判定で拾います)
  • ネガティブプロンプトは見ないので、ネガティブ側にだけ書かれたキャラクターは対象外です
